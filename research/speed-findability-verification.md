### Recommendation — pass gate vs observability

> **Primary pass gate: PageSpeed Insights (lab) — mobile + desktop.**
> **Local reproducibility supplement: `vite preview` + Lighthouse CLI (`npx lighthouse`) checked into the hardening PR as JSON.**
> **Vercel Speed Insights: install in v1 as observability, but NOT the gate.**

Rationale (maps to $0 + Vercel SPA constraints):

1. **PSI is the only tool that is free, zero-code, lab+field, publicly re-runnable, and respected by peer review.** Vercel Speed Insights needs code + deploy + traffic and its dashboard is login-walled and free-tier-capped — peers can't verify without Vercel access. Lighthouse CLI is verifiable but lab-only and localhost-specific unless pointed at prod.
2. **CrUX gate would block forever.** `ericmanabat-dev.vercel.app` is a low-traffic subdomain behind `vercel.app` — CrUX requires public + indexable + sufficient distinct samples (S2 § "Why is real-user data not available"). Field will be empty on day 0; hardening must gate on lab and treat field as "monitor after 28 days".
3. **Local CLI is the only deterministic regression guard.** `npm run build && npx lighthouse http://localhost:4173 --output=json --output=html` gives a before-and-after artifact per PR, suitable for `lighthouserc.json` `assert`. PSI against live can supplement with real Vercel edge headers (compression, caching) that preview lacks.
4. **Vercel Speed Insights still belongs in v1** — it's one `npm i` + one component and gives the only post-launch RUM signal on this $0 stack (once traffic exists). But its signal is delayed and quota-capped — classify as "observability, not gate".

If only one command is mandated for the hardening deliverable, mandate **PSI**; if two, mandate **PSI + Lighthouse CLI against prod URL**.

## 5. Thresholds (what "pass" means)

### 5.1 Core Web Vitals thresholds (per web.dev S1, S2 — assessed at **p75** across page loads; lab gate uses PSI/Lighthouse simulated load)

| Signal | Metric | Good | Needs Improvement | Poor | Hardening **gate** (fail if worse) | Source |
|---|---|---|---|---|---:|---|
| Loading | **LCP** — Largest Contentful Paint | ≤2.5 s | 2.5–4.0 s | >4.0 s | **≤2.5 s** (lab, mobile) | S1 |
| Interactivity | **INP** — Interaction to Next Paint (field) | ≤200 ms | 200–500 ms | >500 ms | **≤200 ms** p75 once CrUX available | S1 |
| Visual stability | **CLS** — Cumulative Layout Shift | ≤0.10 | 0.10–0.25 | >0.25 | **≤0.10** (lab, mobile+desktop) | S1 |
| Loading (supporting) | **FCP** — First Contentful Paint | ≤1.8 s | 1.8–3.0 s | >3.0 s | **≤1.8 s** (informational; fail triggers font/preload fix) | S2 (PSI diagnostics) |
| Responsiveness (lab proxy for INP) | **TBT** — Total Blocking Time | ≤200 ms | 200–600 ms | >600 ms | **≤200 ms** (lab gate proxy; INP non-lab) | S1 note: "Lighthouse cannot measure INP; TBT is proxy" |
| Server | **TTFB** | ≤800 ms | 800–1800 ms | >1800 ms | **≤800 ms** on `localhost:4173` (Vercel edge will be lower once headers set) | PSI opportunity |

### 5.2 Lighthouse category thresholds (lab — PSI + CLI)

| Category | Good (green) | Gate | What drives it on this site |
|---|---|---|---|
| **Performance** | 90–100 | **≥90** on both **mobile** and **desktop** | LCP image, font blocking, JS bundle single-chunk, unused CSS, unoptimized `/assets/*` |
| **Accessibility** | 90–100 | **≥90** (hardening target; currently has `aria-label` on chat, `role=dialog` on modals — verify via audit) | Color contrast on violet accent, `alt` on cert/project images, focus order in modals |
| **Best Practices** | 90–100 | **≥90** | `rel=noopener`, HTTPS, image aspect ratio, `X-Frame-Options` on `/resume.pdf` iframe |
| **SEO** | 90–100 | **≥90** after `robots.txt` + `sitemap.xml` + meta/OG fix (see §7–8) — currently **will fail** without them | Missing `robots.txt`, `sitemap.xml`, `og:image`, JSON-LD, canonical |

> Desktop Performance ≥90 is easier; **mobile ≥90 is the hard gate**. If only one number is demanded, gate on **mobile Performance ≥90**.

## 6. How to Run — Exact Click Path / CLI

Two commands cover the gate; the tester runs **both** (PSI for auditable shareable artifact, CLI for PR-reproducible artifact).

### 6.1 PageSpeed Insights — URL paste (primary gate, lab + field)

PSI at https://pagespeed.web.dev/ (or https://developers.google.com/speed/pagespeed/insights/ which redirects).

**Click path (paste-U happens on live, not preview):**

1. Open **https://pagespeed.web.dev/** in Chrome (or any Chromium) — no login.
2. Paste **`https://ericmanabat-dev.vercel.app/`** (include trailing slash) into the input.
3. Click **Analyze** — wait 30–60 s (Lighthouse lab run per device).
4. When results load, the default is **Mobile**. Record these sections:
   - Top **Performance** score (0–100) — the big circle. This is the gate.
   - **Core Web Vitals Assessment** row (LCP / CLS / INP pill — Good / Needs Improvement / Poor) + **Discover what your real users are experiencing** field strip (will be "No data" on day 0 — screenshot the strip anyway).
   - **Diagnose performance issues** lab block: expand **LCP**, **CLS**, **TBT**, **FCP** rows; expand **Opportunities** + **Diagnostics**.
5. Switch to **Desktop** tab → repeat screenshot + number capture. Desktop and Mobile have separate lab scores; both must be ≥90.
6. Click **Copy Link** (PSI generates `https://pagespeed.web.dev/analysis?url=https://ericmanabat-dev.vercel.app/...`) — paste into hardening evidence. The link is re-runnable by any reviewer.
7. Optional API artifact (for automation): `curl "https://www.googleapis.com/pagespeedonline/v5/runPagespeed?url=https://ericmanabat-dev.vercel.app/&strategy=mobile&category=performance&category=accessibility&category=best-practices&category=seo"` — save JSON alongside screenshot.

### 6.2 Lighthouse CLI — `vite preview` + prod (reproducible lab gate)

CLI is lab-only but portable and checkable into git — it catches PSI-equivalent regressions without a browser paste.

**Prerequisites (one-time):**

```bash

```

**Run 1 — local preview (deterministic, before deploy):**

```bash
npm run build          # tsc -b && vite build  → writes dist/
npm run preview -- --port 4173 --host
# in a second terminal (wait for "Local: http://localhost:4173/"):
npx lighthouse http://localhost:4173/ \
  --preset=desktop \
  --output=html --output=json \
  --output-path=./research/lighthouse-preview-desktop \
  --chrome-flags="--headless --no-sandbox" \
  --throttling-method=simulate

  --form-factor=mobile \
  --throttling.rttMs=150 --throttling.throughputKbps=1638.4 --throttling.cpuSlowdownMultiplier=4 \
  --output=html --output=json \
  --output-path=./research/lighthouse-preview-mobile \
  --chrome-flags="--headless --no-sandbox"
```

**Run 2 — prod (must match PSI target):**

```bash

  --preset=desktop \
  --output=html --output=json \
  --output-path=./research/lighthouse-prod-desktop \

  --form-factor=mobile \
  --output=html --output=json \
```

## 8. Decision: Google Search Console / Bing Webmaster Verification in v1 Scope?

### Verdict: **Include in v1 — ship as a 15-minute hardening fix before launch.**

**Not deferred.** Rationale:

| Factor | Detail |
|---|---|
| **Cost** | $0. HTML-tag verification is a single line: `<meta name="google-site-verification" content="TOKEN">` in `index.html:11` + analogous Bing tag. Token issued in 2 minutes from `https://search.google.com/search-console` → Add property → URL prefix `https://ericmanabat-dev.vercel.app/` → HTML tag. No DNS, no paid plan. |
| **Benefit** | Unlocks the only observability for §7: indexation status, crawl errors, sitemap fetch, Core Web Vitals field data (populates the PSI "real users" strip that is otherwise empty), URL Inspection → Request indexing (accelerates `site:` from weeks to days), and security/manual-action alerts. Without it, findability is unobservable and PSI field stays empty forever. |
| **Risk if deferred** | Hardening "findability checked" becomes unverifiable theater — tester can only screenshot empty SERPs with no path to fix. Also defers `robots.txt`/`sitemap.xml`, which themselves have no value without Search Console to submit them. Portfolio remains invisible on `Q1/Q2` for longer than needed. |
| **Risk if included** | Minimal — adds one `<meta>` + two static files (`public/robots.txt`, `public/sitemap.xml`). No backend, no PII, no analytics. The only leak is the verification token string (public anyway). `vercel.app` subdomain is verifiable via **URL prefix** (domain-level TXT would require `vercel.app` DNS — not available — so HTML tag is the correct method). |
| **Precedent** | Ticket #24 lists verification as optional — but map #20 Out-of-scope ("Paid SEO, paid hosting") does **not** cover this — it's free and aligns with "hardening = findable/fast + peer-reviewable". Issue #21 inventory already flagged `robots.txt`/`sitemap.xml` gap (§2c gap). Deferring would contradict that gap's intent. |

### What "include in v1" concretely means (15-minute slice)

1. **Add** `public/robots.txt`:
   ```
   User-agent: *
   Allow: /
   Sitemap: https://ericmanabat-dev.vercel.app/sitemap.xml
   ```
2. **Add** `public/sitemap.xml` (static — list the only crawlable URL plus assets):
   ```xml
   <?xml version="1.0" encoding="UTF-8"?>
   <urlset xmlns="http://www.w3.org/2000/svg">
     <url><loc>https://ericmanabat-dev.vercel.app/</loc><changefreq>weekly</changefreq><priority>1.0</priority></url>
   </urlset>
   ```
   Note: do not list hash fragments — they are not separate URLs (see §7.2).
3. **Add** in `index.html:11` (after `meta description`):
   ```html
   <meta name="google-site-verification" content="REPLACE_WITH_GSC_TOKEN" />
   <meta name="msvalidate.01" content="REPLACE_WITH_BING_TOKEN" />
   ```
   and `rel=canonical` + OG basics:
   ```html
   <link rel="canonical" href="https://ericmanabat-dev.vercel.app/" />
   <meta property="og:title" content="Eric Gabriel F. Manabat — Portfolio" />
   <meta property="og:description" content="Engineering portfolio, case studies, credentials, and Digital Eric conversational agent." />
   <meta property="og:url" content="https://ericmanabat-dev.vercel.app/" />
   <meta property="og:type" content="website" />
   ```
4. **Add** `&display=swap` to Google Fonts link (`index.html:27-29`): `...&display=swap` to fix CLS/FCP.
5. **Verify** via `https://search.google.com/search-console` → URL prefix `https://ericmanabat-dev.vercel.app/` → Verify via HTML tag, then Sitemaps → Submit `https://ericmanabat-dev.vercel.app/sitemap.xml`, then URL Inspection → `https://ericmanabat-dev.vercel.app/` → Request indexing. Repeat at `https://www.bing.com/webmasters/` for Bing.

If scope pressure is extreme (e.g., ship in next hours with zero token setup), the minimal deferral slice is: ship `robots.txt` + `sitemap.xml` + `display=swap` + `canonical` in the hardening PR, and file a **follow-on 10-minute ticket "Submit GSC + Bing tokens"** before launch. The tokens themselves are deferred, not the files. But recommended is to include tokens in the same PR — the human step is only copying two strings.

## 10. Risks, Caveats & Follow-Ons

- **Preview ≠ Vercel edge.** `vite preview` lacks Vercel compression, edge caching, and `Cache-Control` headers. A preview LCP 200 ms worse than PSI prod is expected — gate on prod PSI, not preview alone.
- **CrUX needs traffic.** Vercel Hobby + `vercel.app` subdomain may never reach CrUX threshold if portfolio gets < ~1k visits/28 days. Then PSI field stays empty forever — lab gate remains authoritative. Document "field N/A — lab authoritative" rather than faking a pass.
- **Hash routing not indexable.** Case studies under `/#case-study/{id}` will never be individually indexed or appear in `site:`; only `/` qualifies. If the map later requires indexable case studies, that is a **routing refactor** (history router + `/case-study/{id}` routes + `sitemap.xml` entries) — spawn a follow-on ticket, not part of this hardening pass.
- **`sharp` pipeline is not build-integrated.** Today's `scripts/optimize-certs.mjs` is Windows-path-bound and only covers certs; `public/assets/projects/*.webp` are manually committed. Follow-on perf-budget ticket may introduce `vite-imagetools` or `sharp`-at-build for project images and enforce a max asset size.
- **Vercel Speed Insights retention.** Hobby caps Speed Insights history and dimensions — treat as nice-to-have RUM, not audit trail. Hardening should not depend on dashboard screenshots for pass.
- **Fonts `display=swap`.** Without it, CLS/FCP fail on slow 3G is guaranteed. This one-param fix dominates the gate — ensure it ships even if other perf work is deferred.
